Задача:
Добавь минимально необходимые комментарии к файлу в зависимости от его типа.

**ОПРЕДЕЛЕНИЕ ТИПА ФАЙЛА НА ОСНОВЕ AST:**
- Если есть JSX элементы и функция возвращает JSX - это **React компонент**
- Если имя функции начинается с "use" и есть хуки внутри - это **React хук**
- Если есть createContext или useContext - это **Контекст**
- Если есть Zustand/Jotai/Redux store логика - это **Store**
- Если есть только функции без JSX и хуков - это **Утилита/Хелпер**
- Если есть TypeScript интерфейсы/типы - это **Типы/Интерфейсы**
- Если есть API запросы и асинхронная логика - это **Сервис**

**Требования к комментариям по типам:**

**ДЛЯ ВСЕХ ТИПОВ:**
- @fileoverview в начале файла с кратким описанием назначения всего файла
- Язык: Русский
- Краткость важнее полноты

**ДЛЯ REACT КОМПОНЕНТОВ:**
- JSDoc блок над компонентом с описанием его назначения и @param для props
- Комментарии ТОЛЬКО к сложной бизнес-логике (условия, вычисления, алгоритмы)
- Краткое описание useEffect с объяснением "зачем" (не "что делает")
- Комментарии к нетривиальным обработчикам событий

**ДЛЯ REACT ХУКОВ:**
- JSDoc блок над хуком с описанием назначения
- @param для каждого параметра хука
- @returns с описанием возвращаемого значения и его структуры
- Комментарии к сложной логике внутри хука
- Описания useEffect/useMemo/useCallback с объяснением "зачем"

**ДЛЯ УТИЛИТ/ХЕЛПЕРОВ:**
- JSDoc блок над каждой экспортируемой функцией
- @param для каждого параметра с типами
- @returns с описанием возвращаемого значения
- Комментарии к нетривиальным алгоритмам или математическим вычислениям

**ДЛЯ КОНТЕКСТОВ:**
- JSDoc над createContext с описанием назначения контекста
- @param для провайдера, если есть параметры
- Комментарии к методам контекста с описанием их назначения
- Описание структуры значения контекста

**ДЛЯ TYPESCRIPT ТИПОВ/ИНТЕРФЕЙСОВ:**
- JSDoc над каждым экспортируемым интерфейсом/типом
- @property для каждого свойства с описанием
- Комментарии к дженерикам и их ограничениям

**ДЛЯ STORE (Zustand/Jotai/Redux):**
- JSDoc над стором с описанием его назначения
- @param для экшенов/сеттеров
- Комментарии к сложным редюсерам или вычисляемым значениям
- Описание селекторов с объяснением их назначения

**НЕ добавляй комментарии к:**
- Простым объявлениям переменных (const, let)
- Очевидному JSX без логики
- Простым деструктуризациям props/state
- Стандартным паттернам (map, filter, условный рендеринг)
- Импортам и экспортам
- Базовым хукам без нетривиальной логики (useState, useContext в простых случаях)
- Очевидным типам и интерфейсам без сложной логики

**КРИТИЧЕСКИ ВАЖНЫЕ ПРАВИЛА:**
- НИКОГДА НЕ СОКРАЩАЙ ФАЙЛ ЧЕРЕЗ МНОГОТОЧИЕ (...) ИЛИ ЛЮБЫМ ДРУГИМ СПОСОБОМ
- ВСЕГДА ВОЗВРАЩАЙ ПОЛНЫЙ ИСХОДНЫЙ КОД С ДОБАВЛЕННЫМИ КОММЕНТАРИЯМИ
- НИКОГДА НЕ УДАЛЯЙ, НЕ ОБРЕЗАЙ И НЕ ЗАМЕНЯЙ ЧАСТИ КОДА НА [...]
- СОХРАНЯЙ АБСОЛЮТНУЮ ЦЕЛОСТНОСТЬ ИСХОДНОГО ФАЙЛА

**Дополнительные правила:**
- НЕ изменяй функциональность кода
- Сохраняй оригинальное форматирование
- Добавляй комментарии ТОЛЬКО там, где это действительно необходимо для понимания
- Предпочитай краткие, но содержательные комментарии
- Если AST не содержит достаточно информации для генерации комментариев - пропусти файл
